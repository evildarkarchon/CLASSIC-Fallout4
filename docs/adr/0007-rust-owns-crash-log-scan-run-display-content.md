# Rust owns Crash Log Scan Run Display Content

Crash Log Scan Run Display Content lives behind one Rust presentation interface so CLI, GUI, TUI, Node, Python, and C++ adapters do not each decide what a run says. The interface projects a Crash Log Scan Run Result or a run event into an ordered sequence of display lines, where every line is a sequence of typed segments carrying Display Labels, counts, paths, and names as values rather than as text spliced into a sentence. Adapters retain Display Layout: ordering and grouping of lines, section headers, colour and emphasis, truncation and wrapping, widget choice, and the interaction affordances offered alongside a recovery decision. This supersedes the clause of ADR-0002 assigning presentation to adapters; every other part of that decision, including typed request projection, event and result mapping, user messaging outside the run's own prose, and the whole Local Ignore recovery continuation contract, stands unchanged.

The split is drawn where it is because naming was already centralized and composition was not. Vocabulary Token and Display Label gave every adopted domain enum a single-sourced label, reachable from the TUI directly and from every other surface through label entry points, and audits in the TUI, GUI, and CLI keep local naming tables from returning. Sentence structure fell outside that boundary, so the same statement of the same run facts is written independently in each frontend and drifts independently. Extending the existing mechanism from names to statements removes that drift without giving Rust any say over appearance, and it keeps the frontends genuinely thin rather than merely thinly named. A named subset of Display Content is identical across frontends and pinned by golden tests — terminal status prose, infrastructure and resume error prose, per-log outcome lines, the Installed YAML Data block, per-event progress lines, and the descriptions of the Local Ignore recovery decisions — while everything outside that subset is Display Layout and free to differ.

Display Content is rendered before it crosses a binding seam, not after. A Crash Log Scan Run Result is not clonable because it retains a one-shot continuation, and adapters already take that continuation before presenting anything, so a binding surface cannot hold the Rust result and render from it later. Each binding therefore renders while the Rust value is still live and carries display lines across as mirrored data alongside the projected result, and renders each observed event into lines inline on the observer callback. The cost is a display-line and display-segment shape mirrored on every binding surface and pinned by the parity baselines, which is why the segment taxonomy is fixed rather than open: it grows only by deliberate decision, never incidentally. Display Content assumes a single language and never interpolates, so counts, paths, and names remain typed fields and pluralization is decided once; this is not an argument that CLASSIC will be translated, only a refusal to make translation a rewrite.

Three things are deliberately outside this decision. Vocabulary Token remains the machine-facing identity and is what structured output, logs, and programmatic consumers match on; a Display Label may be reworded freely and a token may not, so no surface substitutes one for the other. Error kinds that exist as stable codes rather than prose stay token-only by design and gain no Display Label. The Local Ignore recovery decisions offered by Rust remain exactly the two that change what the run does, and the abandonment path every frontend built for itself is encapsulated as one operation over the retained continuation rather than modelled as a third decision; introducing that variant would reshape a type crossing five binding surfaces and is left to a separate decision.

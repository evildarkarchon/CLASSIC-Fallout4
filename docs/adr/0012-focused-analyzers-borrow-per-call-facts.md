# Focused Semantic Analyzers borrow their per-call facts

Each Focused Semantic Analyzer's per-call input borrows the Crash Log facts it reads: text as `&str`, line evidence as slices, and the parsed plugin map, XSE module set, and Crashgen settings snapshot by reference. ADR-0005 had every analyzer accept owned facts so that CXX, Node, and Python could project the analyzers mechanically. ADR-0010 retired Node and Python and made the bridge consumer-driven, and no frontend consumes an analyzer, so every analyzer conformance family is Rust-only. All the owned rule still bought was cost. The private collector copied each Crash Log's combined crash evidence four times (three line vectors and the joined text), plus its plugin map, module set, and settings snapshot, only so that each analyzer could read the copy and drop it (audit S8).

Construction still takes owned YAML Data configuration, because a handle is reusable and outlives any one call. Two derived lists cannot be lent as one slice from what a caller holds: Plugin Evidence's plugin names and FormID Finding's name and prefix pairs. Those are vectors of borrowed items. Results stay owned. If a frontend ever consumes an analyzer, its CXX export owns the facts on the bridge side and lends them to the call, so the cost lands at the boundary that needs it, not on every scan. Everything else in ADR-0005 stands: six public analyzers, typed results without presentation, the private collector, explicit empty results, typed failures, and the byte-identical Autoscan Report requirement.

Shared ownership (`Arc<[String]>` and `Arc<str>` fields) was considered and rejected. It would have kept ADR-0005's wording, but it puts a reference-counting type into public signatures for an internal performance reason, and every direct caller would pay for that allocation shape.

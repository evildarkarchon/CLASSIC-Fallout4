# Retire the Python and Node bindings

CLASSIC no longer ships Python or Node bindings. `python-bindings/` and `node-bindings/` are deleted outright, with no deprecation period, because nothing consumes them: the Node package is private, nothing is uploaded to PyPI, and no wheel or `.node` file is a release asset. They existed only to be held at parity with the Rust core, and that parity was most of the cost of every core change. It took four semantic adapters, three parity baselines, about 150 conformance CI steps, and 474 CXX bridge exports kept alive only for the conformance runner. The last tree that contains them is preserved by the annotated tag `archive/python-node-bindings`. Business logic stays in Rust (ADR-0002, ADR-0004, ADR-0006, ADR-0007, ADR-0009). This decision changes which surfaces expose that logic and how they are proved, not who owns it.

The CXX bridge becomes consumer-driven. It exposes exactly what production code in `classic-cli/src` and `classic-gui/src` calls. One frontend is enough, and callers in tests, benches, and conformance runners do not count. An export lands in the same change as its first production call site and leaves with its last one. Nothing is exported ahead of need, and there is no "coherent API" exception for sibling functions. The gate that enforces this, `cargo xtask cxx-bridge-gate`, fails on orphan exports: functions with no production caller, and types that no surviving export reaches. It parses the bridge with `syn`, matches callers with a strict two-form text scan that fails closed, and keeps no baseline and no waivers. The CLI and GUI production builds catch the opposite failure, a missing export. Some things are never exposed even when a frontend asks: the private contribution collector, Autoscan Report Assembly, report primitives, and fragment-producing aliases (ADR-0005). This boundary is independent of demand and is still enforced by the scan-run manifest's `forbiddenExports`.

The executable conformance engine survives with fewer participants. Rust and CXX are the semantic participants, and CLI, GUI, and TUI remain consumer participants. Every scenario pack stays under the engine, including families that become Rust-only, and the protocol is unchanged. Packs own their expectations. Run plans carry inputs only and withhold expected values. Receipts carry the expectation digest. Validation is central, and comparison is exact after the pack's declared normalization. Expected observations are never generated from a Rust run. Conformance proves behaviour; it never keeps a bridge export alive. CXX applicability comes from a central `tests/conformance/participants.json` rather than from parity rows. Packs still never choose their own participants.

Repository tooling is Rust, and Python leaves the repository. Every surviving gate and tool is one subcommand of a repo-root `xtask` crate, run as `cargo xtask <command>`: the CXX bridge gate, User Settings ownership, the scan-run contract, the YAML Data and app-notification publish tools, the bench helpers, and the conformance engine. Invariants local to one crate become ordinary `cargo test`s in that crate. The single-Tokio-runtime rule becomes clippy `disallowed-methods`. A gate survives only if its invariant outlives the bindings, nothing else already enforces it, and it catches a plausible failure. Each survivor has exactly one named, blocking CI home, listed in `docs/development/repository-gates.md`. xtask links no CLASSIC product crate at run time, so it builds quickly and runs on the Ubuntu publish runners without a proven Linux build of the core. Where the publish validator restates a rule the client enforces, such as cache-file basenames or schema-version ranges, xtask carries its own copy. Dev-dependency agreement tests run both copies over one shared table of cases. The publish jobs build xtask from scratch, with no cache, so a `contents: write` job never restores build output that another workflow wrote.

## Considered options

- **Deprecate the bindings instead of deleting them.** Rejected: with no published artifact and no consumer, a deprecation period has no audience. It would only keep the parity cost alive for longer.
- **Keep the CXX bridge at full core parity for coherence.** Rejected: 474 of its 667 exports were reached only by the conformance runner. Every surviving export now has a reader, and a missing sibling comes back the day a frontend calls it.
- **Keep the Python tooling in a tools-only uv environment.** Rejected: the tooling is slow, and none of its tests ran in CI. As cargo tests in a workspace crate, they run on every PR.
- **Let xtask link the product crates and reuse their rules directly.** Rejected: that would pull Tokio, reqwest, and the Windows-gated crates into every cold `cargo xtask` run, and force the publish jobs onto an unproven Linux build of the core. Agreement tests prove the mirrored rules instead.

## Consequences

This decision partly supersedes ADR-0008. Its execution-proof model survives: scenario-owned expectations, input-only run plans, receipts, central exact comparison, and the separation between semantic and consumer roles. These parts are superseded:

- the four semantic adapters;
- coverage derived from canonical Rust capabilities through parity mappings, together with observed fact IDs and `not_applicable` policy exceptions;
- the per-pack Shadow/Equivalent/Blocking/Retired ratchet and its enforcement tiers, because every pack is blocking by construction;
- the "Checks that remain" list, where CXX source parity is replaced by the orphan-export gate and the Node and Python checks are gone;
- the umbrella compliance module that ADR-0008 deepened, which is deleted, with the engine now living in xtask.

In ADR-0005, mechanical projection of the analyzer surface onto every binding becomes consumer-driven, while its never-exposed rule stands. In ADR-0009, "the parity gates assert their absence" lapses, because the removed entry points no longer exist in Rust. Elsewhere, the mentions of Node and Python adapters in ADR-0002 and ADR-0005 through ADR-0009 describe the surfaces that existed when those decisions were made. Their ownership decisions are unchanged.
